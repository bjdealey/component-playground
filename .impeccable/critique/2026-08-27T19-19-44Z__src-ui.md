## Overall Impression

A confident, well-crafted instrument that nails its "get out of the way" North Star. Held back by one fault line: half the app (Compose canvas) is mouse-only, and the quietest tier of text is also the least readable. The opportunity is reach + legibility of what's already built, not more features.

## What's Working

1. Reach instrumentation — makes an invisible mechanism visible, answering the exact doubt the shared-theme feature manufactures. The product's whole claim, executed.
2. Live two-way preview + per-block PreviewBoundary — the work feels alive and safe; edit→observe loop at zero, honoring "explicit and debuggable."
3. Ruthless material consistency — grayscale + one indigo, mono identifiers, hairline separation, one reused switch idiom. Both assessments confirm independently.

## Priority Issues

[P1] Compose canvas is keyboard/screen-reader-inaccessible. Block wrappers are <div tabIndex=-1>, mouse-only selection (onClickCapture) — no keyboard path to select a block or edit props. Non-selected chrome hidden with opacity:0/pointer-events:none + aria-hidden while ~11 buttons stay tabIndex 0 (~66 invisible focus stops in Dashboard scene, no focus indicator). Add dialog aria-modal but no focus trap/restore. Fails WCAG 2.1.1/2.4.7/4.1.2. Fix: focusable role=button blocks with aria-selected + Enter/Space; inactive chrome display:none with :focus-within reveal; dialog focus trap + restore. → harden

[P2] Faint text tier fails contrast — and it's also the smallest text. text-faint #9aa1ab ≈ 2.6:1 on white carries every eyebrow, count, placeholder, slider hint (below AA 4.5 and large-text 3.0). Detector independently flags the 9.5/10px sizes, which are largely these same hints — lowest-contrast text is also tiniest. Fix: darken faint tier to ~#767c86, or keep #9aa1ab decorative-only and set .hint/eyebrows at text-muted; revisit 9.5/10px hint sizes. → clarify

[P2] Destructive Remove is unguarded and undo is invisible. Block ✕ removes immediately; only recovery is browser Back (hash side effect), unsurfaced. Fix: explicit Undo (history already owned) or 5s undo toast. → harden

[P3] Signature focus ring applied inconsistently. Sidebar search + controls fields get border+glow; Add-dialog search, theme hex, color swatch fall back to plain outline:2px. Fix: apply border+glow to every field. → polish

[P3] DESIGN.md under-documents the chrome's real scale — source of detector noise. 34/38 findings are intentional values (5/7px segmented radii, 3px, micro sizes, switch-track/status colors) not tokenized. Fix: extend rounded (3/5/7/12), type ramp (9.5/10/15), color tokens (#cbd2da, #e6ebfe, status, shadow alphas), or re-run document. → document

## Persona Red Flags

Alex (power user): no shortcut to open Add-block or focus sidebar filter; no command palette to jump to a component (ironic — CommandPalette is a showcased component); "theme off" is 15 clicks, no master toggle; ✕ with no undo hint.

Sam (accessibility): the P1 in full — non-focusable blocks, focusable buttons inside aria-hidden/invisible containers, no dialog focus trap/restore, text-faint fails AA. Keep: focus-visible ring on selects, keyboard sidebar, real-checkbox toggle, aria-live on reach readout + copy status.

Riley (stress-tester): empty state handled; rapid keypresses/mode-flips handled; removing selected block collapses controls. Will hit: garbage in theme hex silently ignored, unguarded ✕, hidden shift-click-to-shrink, selection dropped leaving Interact→Edit.

Developer-owner (daily): core loop well served, Full-source is the right daily check. Friction: no keyboard focus for sidebar filter, no pin/recent for actively-iterated components, unlabeled control-count badge, no signal for a malformed manifest.

## Minor Observations

- transition: width (ComposeStage:136) animates a layout property — fine at click-frequency; transform/explicit steps cleaner. → optimize if jank appears.
- Cryptic block glyphs ↔ ↮ ⇕ ⧉ clash with the otherwise explicit mono-labeled tool. → clarify.
- Sidebar item accessible name "Avatar 14" — trailing count is SR noise.
- No numeric readout while dragging splitters.
- Theme presets in a 92px scroll box (most below the fold — deliberate, protects the sliders).
- Two persistent filled-accent buttons (Copy code, + Add component) are the loudest things on screen — slightly against "almost no filled buttons."

## Questions to Consider

- Component mode has a keyboard-navigable sidebar, yet the Compose canvas is mouse-only — why not make your own CommandPalette the chrome (⌘K unifying sidebar search, Add-block, block selection)?
- Every edit writes the URL hash, so browser Back is a working undo — why keep it secret instead of an explicit Undo, the reassurance the ✕ is missing?
- The reach readout tells you what the theme is driving. Would the inverse — "these 3 blocks ignore every token you've set" — nudge more themeable components?
